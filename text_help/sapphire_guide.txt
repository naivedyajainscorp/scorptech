## Mockup Decision — Settled

**Short answer: Do both, but differently.**

- **sapphire.html** → One combined highlight reel, **max 20–25 seconds**, autoplay, no controls, looping. Right after the "Sapphire Core Suite" section header. One cinematic statement. Anything longer gets abandoned.
- **sapphire_core_suite.html** → Per-module mockup, embedded inside each module section contextually. People on the tour page are already committed readers — the mockup here is credibility, not intro.

The 1.5 minute version is for yourself. Never for the reader.

***

## Overview Blurbs — What Goes In

The content exists in your file's opening paragraphs — but they're too long and too explanatory. What the sapphire.html cards need is **not explanation but pressure** — make the reader feel the problem, then imply Sapphire ends it. 4–5 tight lines, Hank Moody energy. No feature list, no bullet points, no "this module allows you to…"

Think: *"You find out about the problem at Branch 3 because the branch manager mentioned it during a call about something else entirely."* — that's the tone. Pain stated with precision, no dramatics.

Write one per module, present-tense, second-person ("you"). End with a single punchy resolution line. Then CTA.

## Module Tour — Layout Ideas Per Module

### 1. Workplace Management
*Core identity: Real-time command, multi-location, live feed*

- **A. Newsroom Ops Room** — Features scroll as "incoming live feeds" — each card looks like a data stream panel updating in real time. Suits the "live command centre" identity perfectly. Ticker + status-light aesthetic.
- **B. Sticky Command Panel** — Left side mockup stays pinned; right side scrolls through features, each one highlighting a different UI element on the mockup via a pulsing pointer.
- **C. Location Node Network** — An animated SVG hub-and-spoke of location nodes at top. Scroll through features = different nodes light up. Shows scale visually.

→ **Pick A or B.** A is the most tonally resonant. B is the most functionally convincing. Use B if your mockup is clean enough for annotations.

***

### 2. User Management
*Core identity: 23-point permission matrix, access precision, org control*

- **A. Live Permission Matrix Grid** — Rows = roles, columns = the 23 actions. As you scroll through each feature, columns or rows illuminate. The 23-point claim stops being a number and becomes a visual proof.
- **B. Stacked ID Card Deck** — Employee cards fanned like a deck. Each feature highlights a different layer of the card (access tier, location, status). Cards spread on scroll.
- **C. Org Tree with Propagating Permissions** — A hierarchy tree where permission changes visually propagate down branches. Shows the control flow rather than just listing it.

→ **Pick A.** The permission matrix is the differentiator. Making it literally visible is a stronger argument than any paragraph.

***

### 3. Master Data Management
*Core identity: Foundation layer, 5-level location, precision taxonomy*

- **A. Isometric 5-Level Exploded Planes** *(your idea, keep it)* — Five floating layers separate on scroll, each labeled (Building → Floor → Room → Sub-division → Reference). The 5-level drill-down becomes spatial.
- **B. Blueprint Schematic** — Engineering blueprint background. Each master data category (Location, Units, Tax, Brands…) is a labeled "component box" connected by dashed lines. Technical monospace font accents.
- **C. Taxonomy Book Accordion** — Each category is a "chapter" that slides open. Location reveals the nested hierarchy. Units reveals a conversion equation. Tax reveals a rate tree. Each chapter has a distinct mini-visualization.

→ **Pick C, but use A specifically for the Location Hierarchy sub-section.** Master Data is 8 distinct sub-categories — each deserves its own micro-visualization within C's accordion structure.

***

### 4. Inventory Management
*Core identity: 3 structurally distinct tiers, accountability chain, status at all times*

- **A. Three-Zone Kanban Board** — Three columns: Reserve | Distributable Reserve | Active. Item cards flow between columns as you describe each tier. Status labels (assigned, maintenance, missing, restricted) color-coded. This IS how inventory managers think.
- **B. Isometric Warehouse Zones** — Perspective warehouse with three physically separate zones. Items animate between zones. Visually dramatic, spatially intuitive.
- **C. Split-Screen Takeover** — Top = chaos (no system). Bottom = organized three-tier view. A horizontal divider slides upward as you scroll, the organized view consuming the chaotic one. Cinematic, story-driven.

→ **Pick A.** The kanban directly mirrors how a stores manager sees inventory. Immediately legible to your target audience. No explanation needed.

***

### 5. Request Management
*Core identity: 5 request types, approval routing, immutable audit trail*

- **A. 5 Parallel Flow Tracks** — Five horizontal rows, one per request type. Each shows: Raised → Routed → Approved → Executed → Logged. An animated dot travels the active track as you describe it. Demonstrates the "movement layer" concept directly.
- **B. Animated Approval Pipeline** — Single pipeline that forks at a routing node into the correct track. Emphasizes the automated routing mechanism.
- **C. Transaction Receipt Stack** — Each request type renders as a formal custody document — fields, timestamps, approver signature, status stamp. Very deliberate, accountability-first aesthetic.

→ **Pick A.** Five parallel tracks makes the "5 types" instantly scannable. The dot traveling through stages is satisfying and clear. On mobile, tracks stack vertically.

***

### 6. Inspection & Reporting
*Core identity: 6-step cycle, objective criteria, non-overlapping scheduling, trend data*

- **A. Rotating Inspection Wheel** — Circular dial at top. 6 steps as segments. Scrolling rotates the wheel to the next step. Center shows a live score meter filling up. Thematically perfect for "cycles."
- **B. Mockup Walkthrough ("Inspector's Tablet")** — The mockup simulates an inspector completing a checklist — checkpoints animating in, photo being attached, score populating, signature appearing. Features annotate specific moments. *(Perfect fit for your animated mockup.)*
- **C. Before/After Condition Trend** — Two inspection records side by side (3 months apart). Condition bars. A trend line connecting them. Deterioration visible. Features explained around the comparison.

→ **Pick B if your inspection mockup covers the workflow.** It's the most authentic — buyers still on paper clipboards need to SEE the digital process. A is distinctive if the mockup isn't available or complete.

***

### 7. Reporting & Resolution
*Core identity: Repair/Replace/Discard decision tree, lifecycle cost accumulation*

- **A. Branching Decision Tree** — An asset enters "flagged." Three branches grow: Repair, Replace, Discard. Each branch shows its workflow stages. The tree literally grows on scroll.
- **B. Running Lifecycle Cost Counter** — A fictional asset accumulates costs as events happen: Repair ₹12,400 → Repair ₹8,200 → Unscheduled ₹15,000 → Replace ₹45,000 → Total Disclosed. The counter IS the demonstration. The number going up is the product argument.
- **C. Case File Stack** — Each resolution type slides open like a dossier. Inside: fields, costs, outcome stamp, evidence slots. Dark formal aesthetic. Accountability made visceral.

→ **Pick B for the hero moment, A as the structural layout.** Show the decision tree, but make the cost counter the emotional centerpiece. That number is the thing that gets a maintenance manager to book a demo.

***

### 8. Service & Maintenance
*Core identity: Per-unit cycles, skip/reset mechanics, AMC/warranty coverage, spare parts history*

- **A. Gantt-Style Service Timeline** — Assets on vertical axis, time on horizontal. Service events = colored blocks. AMC coverage = continuous bar below each. Overdue = red. This is exactly how maintenance managers think.
- **B. Asset Health Ring Dashboard** — Each asset has a ring (like an activity ring) depleting since last service. On service event, it resets. Side-by-side: two identical models, different workloads, different ring states. Demonstrates per-unit cycles visually.
- **C. Service Record File Jacket** — A physical folder aesthetic that opens up — service history list, coverage documents, spare parts receipts filing in one by one. Each feature "adds a document" to the jacket.

→ **Pick A.** A Gantt layout is industry-native for maintenance. Any maintenance manager who sees it immediately knows what they're looking at and that it maps to their mental model. That recognition is worth more than novelty.

***

### 9. Smart Analytics
*Core identity: 8 analytics domains, data → intelligence, always current, no additional effort*

- **A. Data Flow Transformation** — Left: raw event stream (icons: issue, return, inspection, repair) flowing in continuously. Center: a transformation zone. Right: charts and KPI cards rendering from that data. Animates continuously. "Data → Intelligence" made visual.
- **B. Dashboard Spotlight Annotation** — The full analytics mockup occupies most of the section. As you scroll through each domain (Cost, Maintenance, Inventory, Fleet…), an animated spotlight/highlight ring circles the relevant panel on the dashboard. Features literally point to themselves.
- **C. Live Animated Metric Cards** — A grid of stat cards with animated counters, sparklines drawing themselves, pie charts filling in real time. The section demonstrates analytics by being analytics.

→ **Pick B if your analytics mockup covers multiple domains.** The spotlight annotation turns the mockup into a guided product tour — the most convincing layout possible for a data product. Pick A if the mockup is partial or single-screen.

## A. Newsroom Ops Room

The entire section feels like a live operations control room. Dark background. Each feature card mimics a "live data feed panel" — thin border, a blinking green status dot in the corner, a subtle scan-line or pulse animation suggesting live data. Features don't just sit there — they appear to be *receiving* information.

```
┌─────────────────────────────────────────────────────┐
│  ● LIVE    WORKPLACE COMMAND — BRANCH OVERVIEW       │
├──────────────────┬──────────────────┬───────────────┤
│ ● Branch Delhi   │ ● Branch Mumbai  │ ● Branch Pune │
│ OPEN · 2 shifts  │ OPEN · 1 shift   │ CLOSED        │
│ 47 assets live   │ 31 assets live   │ —             │
├──────────────────┴──────────────────┴───────────────┤
│  ▼ LIVE FEED ──────────────────────────── 04:12 AM  │
│  [Tool issued] Bay 3 · Rahul Sharma · Torque Wrench │
│  [Inspection] Bay 1 · Shift start gate · PASSED     │
│  [Maintenance] Lift #2 dispatched · ETA 2hrs        │
└─────────────────────────────────────────────────────┘
```

Each **feature** of Workplace Management gets its own "feed panel" below this header. As you scroll, a new panel slides in from the right — like a new data stream opening. No static cards. Everything pulses.

**Mobile:** Panels stack full-width. Status dot + feed lines still visible. Still reads like a live dashboard.

## B. Sticky Command Panel

Classic scroll-linked layout. The mockup (your pre-built one) is **pinned to the left** using `position: sticky`. The right side is a tall scroll column — each feature is a block with enough height that scrolling past it triggers a change on the mockup.

```
┌───────────────────┬─────────────────────────────────┐
│                   │                                  │
│   [YOUR MOCKUP]   │  Unlimited Workplaces            │
│                   │  ─────────────────────           │
│  ← stays fixed    │  No cap on how many locations    │
│    as you scroll  │  you register...                 │
│                   │                                  │
│  Pulsing ring on  ├─────────────────────────────────┤
│  the location     │                                  │
│  switcher UI      │  Overlapping Shift Support       │
│  element          │  ─────────────────────           │
│                   │  Define shifts that overlap...   │
│                   │                                  │
│                   ├─────────────────────────────────┤
│  Ring moves to    │                                  │
│  shift column     │  Open/Closed Intelligence        │
│  on mockup        │  ...                             │
└───────────────────┴─────────────────────────────────┘
```

JS `IntersectionObserver` watches each right-side feature block. When one enters view, it fires a class on the mockup that moves the pulsing highlight ring to the relevant UI element.

**Mobile:** Sticky doesn't work vertically stacked. Mockup goes on top as a static image or short autoplay clip. Features below it. No pointer needed — the sequence implies the connection.

***

## C. Location Node Network

Top of the section: a full-width SVG canvas with an animated hub-and-spoke diagram. Central node = "HQ/Owner View." Branches = locations. Each node has a live status dot and a label. As the user scrolls through features, the relevant node or connection pulses/highlights.

```
                    ● HQ Dashboard
                   /    |    \
                  /     |     \
         ● Delhi  ● Mumbai  ● Pune  ● Jaipur
           OPEN     OPEN    CLOSED    OPEN
           │
     [pulsing when "Live Activity Log" feature is active]
```

Connector lines animate (stroke-dashoffset drawing effect) when a feature that relates to multi-location is described. When "Role-Based Access" feature is active — each node shows a tiny lock/unlock icon. When "Real-Time Snapshot" is active — each node shows an asset count badge popping in.

**Mobile:** SVG scales down, shows 3 nodes max with scroll (carousel or tap). Compact but still communicates the network idea.

## Which One Actually Wins

| Option | Strength | Risk |
|---|---|---|
| A | Tonally strongest, most original | Requires careful dark-mode design |
| B | Most convincing for buyers, uses your mockup | Your mockup must be clean enough for spotlight |
| C | Most conceptually literal to "multi-location" | Can feel like a generic org chart if not styled aggressively |

**My honest pick: A on the tour page, B if this section also appears inline on sapphire.html with the mockup.** A is a *vibe*. B is a *proof*. You want both at different moments.
